Add email + password authentication

Drafted by Codex · acme-web · just now

Goal

Add a boring, production-safe email/password login flow backed by Postgres sessions, without changing the existing dashboard experience.

Approach

  1. Validate signup and login payloads with zod.
  2. Hash passwords with bcryptjs and never return them from an API response.
  3. Create an opaque session token, store only its hash in Postgres, and set an HttpOnly cookie.
  4. Wire the existing LoginForm to the new route and surface field-level errors.
No schema changes beyond the new sessions table. No auth provider or email delivery in this slice.

Changes

  • app/api/auth/route.ts — POST login and signup handlers.
  • lib/password.ts — hash and verify helpers.
  • lib/session.ts — session issue, lookup and revocation.
  • components/LoginForm.tsx — submit states and inline errors.
  • db/migrations/*_sessions.sql — sessions table and indexes.

Verification

  • Run the auth unit tests and the login flow against a disposable Postgres database.
  • Check that logout revokes the session and that cookies are cleared.
  • Confirm no password or raw session token is logged.

Open questions

  • Session lifetime: 7 days or 30 days?
  • Do we need login rate limiting in this slice?
